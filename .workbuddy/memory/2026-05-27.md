## 清理时机优化 + 空白对话处理（第二轮）

### 调研结论
- OpenClaw 会话管理：`~/.artifexnexus/.openclaw/state/agents/<agentId>/sessions/sessions.json`（append-only）
- Transcript 文件：`.jsonl` 格式，`sidecar_sessions.py` 的 `_extract_session_summary` 返回 `hasTranscript` 字段
- OpenClaw 本身无自动清理机制，删除会话仅给 transcript 文件名加 `.deleted.` 后缀
- 空白对话原因：`hasTranscript=false` 的会话仍在列表中，点开时 transcript 文件不存在 → 返回空消息

### 优化措施
1. **SessionSummary 类型**（`openclaw.ts`）：新增 `hasTranscript?: boolean` 字段
2. **即时过滤**（`ChatControlBar`）：会话加载后立即隐藏 `hasTranscript=false` 且创建 >24h 的空会话
3. **延迟清理**（`ChatControlBar`）：会话加载成功后延迟 30s 执行 IndexedDB/localStorage 清理，不阻塞 UI
4. **移除竞争**（`ChatView`）：删除 ChatView 中的启动清理 useEffect，消除与 ChatControlBar 的 IPC 竞争
5. **回调通知**：ChatControlBar 通过 `onCleanupComplete` 通知 ChatView 清除 chat-service 内存缓存 + 刷新列表

## 空白对话修复 + IndexedDB 分块清理（第三轮）

### 根因
- **Rust `SessionSummary` 结构体缺少 `has_transcript` 字段**，手动反序列化也未提取，导致 sidecar 返回的 `hasTranscript` 在 Rust 层被静默丢弃
- TypeScript 端的 `hasTranscript` 永远为 `undefined`，`s.hasTranscript !== false` 恒为 `true`，过滤失效

### 修复
1. **Rust**：`openclaw_sessions.rs` 的 `SessionSummary` 新增 `pub has_transcript: Option<bool>`，反序列化中提取 `s["hasTranscript"].as_bool()`
2. **IndexedDB 分块清理**：`deleteSessionsBatch` 重写为分块执行（每 5 条一块，块间 `setTimeout(0)` yield 事件循环），避免长时间阻塞主线程
3. **Rust + TypeScript 双端编译通过**
