## UI 约定

### Select/下拉框规范
**必须使用设计令牌，禁止硬编码 `bg-white/[0.0x]`/`backdrop-blur`：**
```
rounded-md border border-input bg-input px-2 text-xs text-foreground 
focus:outline-none focus:ring-1 focus:ring-ring 
[&_option]:bg-card [&_option]:text-foreground
```
- `rounded-md`（6px）= 输入框圆角规范（design-language.md §5）
- `border-input` / `bg-input` = 输入框 L3 色（HSL 0 0% 12.2%）
- `focus:ring-ring` = 品牌蓝焦点环（213 78% 65%）
- **禁止** `appearance-none`（会隐藏原生下拉箭头）
- **禁止** 玻璃效果（`backdrop-blur`）用于输入控件，玻璃仅用于卡片/弹层（§3.5）

### Blender 触发器钩子
- 钩子注册入口：`blender_addon/__init__.py` 的 `register()`
- 钩子函数必须用 `@bpy.app.handlers.persistent` 装饰
- 使用 `*args` 签名兼容不同 Blender 版本
- 事件通知通过 `MCPServer.broadcast_trigger_event()` → `asyncio.run_coroutine_threadsafe`
- 前端的触发器横幅根据 DCCStatusContext 动态显示/隐藏

## ArtClaw vs Artifex Nexus Blender 插件差异分析

完成全面对比分析，产出文档：`docs/specs/blender-plugin-comparison-artclaw-vs-artifex.md`

### 关键发现
- **事件覆盖**: Artifex Nexus 缺 `file.save.pre`、去重保护、反重载保护（P0）
- **事件系统**: ArtClaw 双系统（本地执行 + HTTP 转发），Artifex 单系统（MCP 广播）
- **UI 反馈**: Artifex 缺 Blender 内触发结果弹窗
- **Artifex 优势**: render.post 事件、Gateway+Sidecar 编排、部署校验、多版本兼容

### 建议优先级
- P0（必须）：save_pre handler、反重载 sys.modules wrapper、500ms 去重
- P1（应该）：payload 增强、面板状态详情
- P2（远期）：popup 通知、SDK 层、Chat Panel

## Gateway 崩溃/超时问题诊断与修复

### 诊断结论
Gateway 本身**没有崩溃**，真正的问题是 `nexus-tool.fetch_types` 阻塞 sidecar：

**因果链**：
1. `fetch_types` → `bridge.call_tool(timeout=30)` 同步阻塞 sidecar stdin 循环
2. 阻塞期间其他 RPC 全部排队超时 → Rust 端报 "sidecar 响应超时"
3. 每次启动后 30-60s 必定触发（前端轮询 fetch_types）

### 修复（nexus_tool_rpc.py）
- MCP `call_tool` timeout: **30s → 5s**（短超时避免阻塞 sidecar）
- **新增结果缓存**：`_fetch_types_cache[dcc] = (timestamp, result)`，TTL 60s
- 连接失败/查询失败结果也缓存（避免重复阻塞）
- 桥未连接 → 立即返回错误，不阻塞
