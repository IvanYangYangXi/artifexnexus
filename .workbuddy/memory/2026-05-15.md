## stop_gateway 参数错误 + 健康监控确认（11:49）

**发现**：`runtime.stop_gateway(*, keep_health_monitor: bool = False)` 是 keyword-only 函数，但 `_clean_install` 和 `_handle_openclaw_bootstrap` 都传了位置参数 `stop_gateway(openclaw_home)` → TypeError 被 catch 静默吞掉 → Gateway **从未被真正停止**。

**健康监控机制**（`runtime.py`）：
- `_start_health_monitor()` 启动 daemon 线程，每 5s 检测 gateway 存活
- gateway 崩溃 → 自动重启（速率限制 3次/60s）
- `stop_gateway()` 会同时设 `_health_monitor_started = False` 停止监控
- 但因为参数错误，`stop_gateway()` 从未执行 → health monitor 始终活跃

**修复**：
- `bootstrap.py:670`：`_runtime.stop_gateway()` 去参数
- `sidecar.py:191`：同样去参数，加注释说明停止 health monitor

**结论**：重装时 Gateway 会正确停止 + 健康监控线程退出，不会触发自动重启。

## WinError 32 终极修复 — SQLite 在线 backup + 容错单文件拷贝（13:10）

**用户报错（13:09:01）**：`Gateway 已停止` 紧接 `备份失败: [WinError 32] 另一个程序正在使用此文件，进程无法访问`，30s 后 install 也超时。多次修复未解。

**真正根因**（前几轮没定位准）：
- OpenClaw Gateway 是 Node.js 进程，启动了**嵌入式 Chromium**（`state/browser/openclaw/user-data/`）做 web automation
- Chromium 进程通常以 detached 模式启动，**不在 stop_gateway 的 taskkill /T 进程树内**
- 即使 Gateway 主进程死了，孙进程持续持有 SQLite WAL 锁、jsonl 写锁
- `shutil.copy2` (CopyFile2) 默认请求 `FILE_SHARE_READ|WRITE`，遇到独占锁 (Node.js fs.open 'wx', SQLite LockFileEx) → ERROR_SHARING_VIOLATION (32)
- 当前代码在 `_backup_for_reinstall` 里**任一文件失败就抛异常**，导致整个 manifest 不写入，restore 拿不到 timestamp 落到 fallback install 路径，install 又卡 30s 超时

**修复方案**（治本 + 治标）：

1. **`_sqlite_backup` 在线热备份**（治本，bootstrap.py 新增 27 行）
   - 用 sqlite3 内建 `Connection.backup()` API + `mode=ro&immutable=1` URI
   - SQLite backup API 设计就是允许"源被另一进程持有写锁时仍可备份"
   - 单测验证：`conn = sqlite3.connect(src); conn.execute(...)` 持锁状态下 `_sqlite_backup(src,dst)` 仍成功，dst 数据完整

2. **`_safe_copy_file` 容错单文件拷贝**（治标，bootstrap.py 新增 38 行）
   - 先 `shutil.copy2`（快路径），失败回退到 `open(src,'rb') + open(dst,'wb') + chunk read/write`（绕过 CopyFile2 共享语义）
   - **任何错误返回 (False, err) 而非抛异常**

3. **`_copytree_ignore_patterns` 重写**（替换原 shutil.copytree 调用）
   - 改用手动 os.walk + `_safe_copy_file`，单文件失败追加到 `skipped` 列表，不中断目录拷贝
   - 4 处调用点均传入 `skipped=skipped`

4. **Manifest 增加 `skipped` 字段**
   - `_backup_for_reinstall` 顶部 `manifest["skipped"] = []`，所有失败文件累计
   - sidecar `_handle_openclaw_backup` 透传 `skipped_count` + `skipped[:20]` 到响应
   - 前端 `BackupResult` 类型 + `SystemPage.tsx` 把跳过文件数和最多5条路径写入日志，用户可见

**改动**（4 文件 +90/-20 行）：
- `bootstrap.py` — 新增 `_sqlite_backup` + `_safe_copy_file`，重写 `_copytree_ignore_patterns`，替换 4 处 shutil.copy2，manifest 加 skipped
- `sidecar.py` — `_handle_openclaw_backup` 响应加 skipped_count/skipped
- `openclaw.ts` — `BackupResult` 加 skipped_count/skipped 字段
- `SystemPage.tsx` — 备份完成日志显示跳过数 + 最多5条文件名

**单元测试**：3/3 通过
- `_safe_copy_file` 普通拷贝 OK
- `_sqlite_backup` 在源被另一连接持锁时 OK，目标 db 数据完整（rows=[(42,)]）

- `models.providers` **永不加入 replacePaths**。provider 删除通过 `null` 值表达（OpenClaw "null deletes a path"），增/改用标准 merge

- `dumpToState` + `createInitialState` 新增 `originalProviderIds: string[]` 字段，从 dump 提取并存到 LOAD_SUCCESS state
- 每个 provider 的 `--replace-path models.providers.<pid>.models` 恢复（之前因跟 models.providers 取消），因为现在 models.providers 不在 replacePaths 里，细路径不再冲突

**Bug 2 修复**（2 处）：
- `SettingsAction` 新增 `{ type: "MARK_DIRTY" }` 动作

**结果**：
