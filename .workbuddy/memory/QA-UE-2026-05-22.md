## P0 — 阻断性问题

### P0-1：Sidecar 未注册 UE RPC 方法

**文件**: `sidecar.py` METHOD_TABLE (line 1685-1750)
**现状**: 仅有 `openclaw.dcc.blender.detect|install|uninstall` 三个 Blender RPC。无任何 `openclaw.dcc.unreal.*` 入口。
**影响**: `install_ue_plugin()` / `uninstall_ue_plugin()` / `find_ue_versions()` 虽然已在 `dcc_installer.py` 中实现，但**任何外部调用方都无法通过 JSON-RPC 触达它们**。
**修复**: 新增 3 个 RPC handler + 注册到 METHOD_TABLE：
- `openclaw.dcc.unreal.detect` → `_handle_openclaw_dcc_unreal_detect`（调用 `find_ue_versions()` + `check_ue_version_compatibility()`）
- `openclaw.dcc.unreal.install` → `_handle_openclaw_dcc_unreal_install`（调用 `install_ue_plugin()`）
- `openclaw.dcc.unreal.uninstall` → `_handle_openclaw_dcc_unreal_uninstall`（调用 `uninstall_ue_plugin()`）

### P0-2：Tauri IPC 层未暴露 UE 命令

**文件**: 
- `apps/desktop/src-tauri/src/lib.rs:71-125` (invoke_handler 无 UE 条目)
- `apps/desktop/src-tauri/src/commands/openclaw.rs` (无 UE IPC command)
- `packages/apps/web/src/ipc/openclaw.ts` (仅 `installBlenderAddon` / `uninstallBlenderAddon`)

**现状**: Tauri Rust 层只有 Blender 的 IPC 桥接命令。UE 命令完全不存在。
**影响**: 前端无法通过 `invoke()` 调用 sidecar 的 UE RPC。
**修复**: 仿照 Blender 模式添加：
1. Rust: `commands::openclaw::openclaw_dcc_unreal_detect|install|uninstall`
2. TS IPC: `detectUEVersions()` / `installUEPlugin(version, projectPath)` / `uninstallUEPlugin(version, projectPath)`

### P0-3：前端 UE 安装是 TODO 占位

**文件**: `SystemPage.tsx:500-512`
**现状**: 
```tsx
// TODO: 调用 sidecar RPC 执行 install_ue_plugin
addLog(parentId, "warn", `[${child.label}] UE 安装功能待 Tauri IPC 接入`);
setItems(... state: "installed" ...);  // 假标记为已安装
```
**影响**: 用户点击"安装"按钮后提示未接入，但状态被假标记为 `installed`。
**修复**: P0-1 + P0-2 完成后，替换为真实 RPC 调用。

## P1 — 功能性缺陷

### P1-1：MCP Bridge 状态检查仅覆盖 Blender

**文件**: `sidecar.py:991-1087` (`_handle_openclaw_gateway_mcp_bridge_status`)
**现状**: 返回字段为 `blenderConnected` / `blenderServerRunning` / `blenderAddress` / `blenderError`。UE 完全没有对应的连通性检查。
**影响**: 无法在控制面板中查看 UE MCP 连接状态。
**修复**: 扩展返回结构或新增 `openclaw.gateway.mcp_bridge.unreal_status` RPC，参考 `check_blender_mcp_connection()` 实现 `check_unreal_mcp_connection()`。

### P1-2：UE 插件安装未记录部署清单

**文件**: `dcc_installer.py:310-365` (Blender `install_dcc_addon` 调 `_record_deployment()`)
**现状**: `install_ue_plugin()` 不会调用 `_record_deployment()`。Blender 安装会记录到 `deploy-manifest.json`。
**影响**: 
- `openclaw.deploy.validate` 不会检查 UE 插件完整性
- 备份/恢复流程遗漏 UE 插件状态
**修复**: `_install_ue_plugin_files()` 完成后调用 `_record_deployment(deployment_id, src_dir, target_dir, source_version)`。

### P1-3：`install_ue_plugin` 未注册 tool-sources

**文件**: `dcc_installer.py:363` (Blender 调 `_try_register_tool_source(src_dir)`)
**现状**: UE 安装后不会注册到 `tool-sources.json`。
**影响**: UE 的 Python 工具脚本不在侧边栏/触发器注册表中。
**修复**: 安装成功后调用 `_try_register_tool_source(str(src_dir / "Content" / "Python"))`。

### P1-4：`uninstall_ue_plugin` 硬删除所有文件（含 Lib/）

**文件**: `dcc_installer.py:718-750`
**现状**: `shutil.rmtree(target_dir)` 直接删除整个 `Plugins/ArtifexNexusForUnreal/`，包括 `Content/Python/Lib/`。
**影响**: 与之前制定的"重装保留 Lib/"规则冲突 —— 单独卸载时也会丢失 pip 依赖。
**建议**: 
- 方案 A（推荐）：卸载时保留 `Lib/`，提示用户手动清理
- 方案 B：卸载前询问用户是否也删除 Lib/

## P2 — 体验优化

### P2-1：前端 fixture 数据是硬编码假数据

**文件**: `SystemPage.tsx:120`
**现状**: 
```tsx
{ id: "unreal_engine", name: "Unreal Engine", ... 
  children: [{ label: "UE 5.7 主项目", version: "5.7.0", 
               installPath: "D:\\Proj\\MyGame", ... }] }
```
**影响**: 每次打开设置页都显示固定假数据，不反映真实安装状态。
**修复**: P0 完成后，启动时调用 `detectUEVersions()` 动态填充。

### P2-2：ICON_LABELS 单字母

**文件**: `SystemPage.tsx:128`
**现状**: `unreal_engine: "U"` — 与其他 DCC 单字母一致，但不够直观。
**建议**: 可改为 `"UE"`（两个字符也 OK）。
