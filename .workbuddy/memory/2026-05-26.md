## Python Sidecar scan/refresh 缓存（性能优化 v2）

### 问题根因
- 前端 SkillsPage + RightPanel 同时发 4 个并行 RPC，Rust 端 Mutex 串行执行
- **每个 RPC 都触发完整文件系统扫描**：`hub.scan_all_skills()` / `registry.refresh()` 每次调用都重新扫磁盘
- 4 个调用总耗时 = 累加（200-800ms），而非取最大值

### 修复方案
- `skill_rpc.py`：添加 `_cached_scan(hub)` + `_invalidate_scan_cache()`，TTL=3s
- `nexus_tool_rpc.py`：添加 `_cached_refresh(registry)` + `_invalidate_refresh_cache()`，TTL=3s
- 读操作（list/detail/search） → 走缓存（第 2/3/4 次调用 <1ms）
- 写操作（所有 mutation） → 先失效缓存再 scan/refresh
- **效果**：同一批 RPC 中只有第 1 次扫盘，后续都命中缓存，总耗时降至单次扫描时间

## Max 插件第三轮修复（12:10-12:25）--- sys.path 优先级 + artclaw 模块名劫持

### 症状
1. Max 可以正常启动
2. 不断触发新的 Max 进程启动
3. 看不到插件面板入口

### 根因（CHS Max.log 证据）
```
ERR: File "startup.py", line 57, in _deferred_startup
    from mcp_server import create_server, register_builtin_tools, DEFAULT_PORT
ImportError: cannot import name 'create_server' from 'mcp_server'
(C:\...\CHS\scripts\DCCClawBridge\core\mcp_server.py)
```

**加载顺序导致模块劫持**:
1. artclaw 的 `artclaw_startup.ms` → `artclaw_startup.py` 先执行
2. artclaw 的 integrity_check fallback 将 `DCCClawBridge/core/` 注入 sys.path

4. ImportError → `_create_menu()` 未执行 → 无面板入口
5. 整个启动链失败 → 进程崩溃/重启循环

### 修复
`startup.py._deferred_startup()` 开头增加 sys.path 优先级修复：
- 把 `_addon_dir`（`scripts/artifex_nexus/`）重新提到 sys.path 最前面
- 即使 artclaw 已修改 sys.path，artifex 的模块仍优先匹配
- 同步部署到 CHS + ENU 所有 startup.py 副本

### 关键教训
- **用户 Max locale 是 CHS（中文）**，所有部署操作必须覆盖 CHS 目录
- artclaw + artifex 共存时，模块名冲突是系统性风险（mcp_server, max_adapter, trigger_dispatcher 等）
- 解决思路：自包含路径优先，不能依赖 sys.path 自然顺序

## Skill 同步按钮 Bug 修复（17:07）

### 症状
Skill 详情页显示"源码有更新"，点击列表卡片上的"同步"按钮后仍然显示"源码有更新"，同步不生效。

### 根因
`packages/platform/skill/src/artifex_nexus/skill/installer.py:356` 中 `compare_skill_dirs()` 参数顺序反了：

```python
# BUG（installer.sync 中）:
status = compare_skill_dirs(source_dir, target_dir)
# source_dir → 被当作 installed_dir（第1参数）
# target_dir → 被当作 source_dir（第2参数）
# → 方向检测完全反转

# 正确（_rpc_helpers.py 中 _skill_check_sync 的调用）:
status = compare_skill_dirs(install_dir, source_dir)
```

**影响链**：
1. `compare_skill_dirs(source_dir, target_dir)` 参数反了
2. 源码有新增文件时，被检测为 `inst_ahead`（而非 `src_ahead`）
3. → 状态变成 `INSTALLED_NEWER` 或 `MODIFIED`
4. → sync 方法的分支 `status.state == SyncState.SOURCE_NEWER` 不命中
5. → `_do_sync_copy()` 从不执行 → 文件从不复制

而 UI 显示"源码有更新"用的 `_skill_check_sync` 调用是**正确的**（`install_dir, source_dir`），所以 UI 正确检测到差异，但同步操作因参数反了而失败。

### 修复
`installer.py:356`：`compare_skill_dirs(source_dir, target_dir)` → `compare_skill_dirs(target_dir, source_dir)`

### 对比 artclaw
仔细检查发现 `compare_skill_dirs` 的文档和 `_skill_check_sync` 的调用都明确第1参数是 installed_dir，但 `installer.sync` 的调用是从 artclaw 复刻时参数顺序就用反了（artclaw 可能也有同样的 bug）。

## 隐藏/显示面板导致其他面板高度变化 + "Previous layout not found" 修复（18:37）

### 问题
1. 隐藏/显示分栏 → 其他分栏高度变化，折叠态也被强制拉伸
2. Console Error: "Previous layout not found for panel index -1"（`p.collapse()` 调用时）

### 根因分析
**问题1 根因**：`renderDualColumnLayout` 中 `rightPanels.filter(p => !hiddenRegistry[id])` **过滤掉**隐藏面板 → 隐藏面板从 PanelGroup DOM 中移除 → PanelGroup 把腾出的空间按比例分配给剩余面板 → 折叠态面板也被拉伸。

**问题2 根因**：`useEffect([open])` 中调用 `p.collapse()/p.expand()` 命令式 API。当 Panel 刚被重新加入 DOM（如在双列之间切换、或者隐藏后恢复）时，react-resizable-panels 的布局注册尚未完成（index=-1），此时调用 `collapse()` 报错。`try/catch` 无法捕获此错误因为它来自 react-resizable-panels 内部的 `console.error`。

### 修复方案 — 完全声明式尺寸控制

**核心策略**：废弃所有命令式 `collapse()/expand()`，改用 `minSize`/`maxSize` 声明式锁定面板尺寸。

1. **不再过滤隐藏面板** — 所有 Panel **始终保留在 PanelGroup DOM 中**，通过 `minSize=maxSize` 锁定尺寸
2. **尺寸锁定规则**（`effectiveMinSize`/`effectiveMaxSize`）：
   - 展开态：`minSize={minSize}`, `maxSize={undefined}` → 可拖拽
   - 折叠态：`minSize={collapsedSize}`, `maxSize={collapsedSize}` → 锁定在 header 高度
   - 隐藏态：`minSize={hideSizeRef.current}`, `maxSize={hideSizeRef.current}` → 锁定在隐藏前的实际尺寸
3. **展开时用 RAF + resize()**（仅此一处命令式调用，且延迟到下一帧布局注册完成）
4. **隐藏态派生自 context**：`hidden = controlledHidden ?? ctx.hiddenRegistry[id] === true`，HiddenTabBar 点击直接生效
5. **handleHide 记录当前尺寸**：`hideSizeRef.current = p.getSize()`，隐藏时锁定此尺寸避免空间重分配
6. **toggle 恢复时不强制 setOpen(false)**：保持隐藏前的折叠/展开状态

### 改动文件
- `packages/ui/src/components/collapsible-panel.tsx`:
  - 移除 `uncontrolledHidden`，hidden 派生自 `ctx.hiddenRegistry`
  - 移除 `useEffect([open])` 的 `p.collapse()/p.expand()`
  - 移除 `useEffect([hidden])` 的 `p.collapse()`
  - 新增 `effectiveMinSize`/`effectiveMaxSize` useMemo 声明式尺寸控制
  - 新增 `hideSizeRef` 记录隐藏前尺寸
