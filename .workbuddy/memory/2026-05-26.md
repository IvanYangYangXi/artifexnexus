## Max 插件第三轮修复（12:10-12:25）--- sys.path 优先级 + artclaw 模块名劫持

### 症状
1. Max 可以正常启动
2. 不断触发新的 Max 进程启动
3. 看不到插件面板入口

### 根因（CHS Max.log 证据）
```
ERR: File "startup.py", line 57, in _deferred_startup
    from mcp_server import create_server, register_builtin_tools, DEFAULT_PORT
ImportError: cannot import name 'create_server' from 'mcp_server'
(C:\...\CHS\scripts\DCCClawBridge\core\mcp_server.py)
```

**加载顺序导致模块劫持**:
1. artclaw 的 `artclaw_startup.ms` → `artclaw_startup.py` 先执行
2. artclaw 的 integrity_check fallback 将 `DCCClawBridge/core/` 注入 sys.path
3. artifex 的 `from mcp_server import create_server` 找到 artclaw 的 `mcp_server.py`（没有 `create_server`）
4. ImportError → `_create_menu()` 未执行 → 无面板入口
5. 整个启动链失败 → 进程崩溃/重启循环

### 修复
`startup.py._deferred_startup()` 开头增加 sys.path 优先级修复：
- 把 `_addon_dir`（`scripts/artifex_nexus/`）重新提到 sys.path 最前面
- 即使 artclaw 已修改 sys.path，artifex 的模块仍优先匹配
- 同步部署到 CHS + ENU 所有 startup.py 副本

### 关键教训
- **用户 Max locale 是 CHS（中文）**，所有部署操作必须覆盖 CHS 目录
- artclaw + artifex 共存时，模块名冲突是系统性风险（mcp_server, max_adapter, trigger_dispatcher 等）
- 解决思路：自包含路径优先，不能依赖 sys.path 自然顺序

**提交**: 86def95 → pushed to main

## Max CHS locale 同步缺失修复（13:22）

### 症状

### 根因
`_sync_max_locales()` 有两个 bug:
1. **选错同步源**: 用户有 `2023/` 和 `2023 - 64bit/` 两个目录。`install_dcc_addon` 优先安装到 `2023 - 64bit/ENU`，但 `_sync_max_locales` 先遍历到 `2023/ENU`（无 addon）就把它当主源
2. **错误静默吞掉**: `shutil.copytree` 源不存在 → `OSError` 被 `except: pass` 吞掉，CHS 永远同步不到

- **代码修复**: `_sync_max_locales()` 改为先验证 `artifex_nexus/` 实际存在再作为同步源，找不到则回退到任意存在 addon 的 locale；并为 copy 失败增加日志
- **清理**: 删除 `2023/ENU/scripts/startup/` 中的残留启动脚本

## Max MCP Server 启动失败 + UI 面板（13:30-13:33）

### MCP Server 启动失败根因
`artifex_nexus_sdk/mcp_server.py::_start_server()` 中 `for attempt in range(self._max_port_probe)` 当 `max_port_probe=0`（Max 固定端口模式）时循环体不执行，Python `for...else` 触发 `else` 分支直接 `return`，server 从未绑定端口。

**修复**: `max_attempts = max(self._max_port_probe, 1)` 确保至少尝试一次。
同时 `max_port_probe=0` 时端口被占用直接 `raise`（不探测其他端口）。

## UI 面板状态同步 + 窗口层级修复（13:38）

### 状态同步（点击启动报"端口被占用"）
**根因**: `startup.py` 通过 `mcp_server.create_server()` 创建 server 实例 A，`__init__.py` 的 `_get_mcp_server()` 创建实例 B。UI 面板调用 `start_server()` → `_get_mcp_server()` 返回 B → `B.is_running=False` → 尝试绑端口 → 端口已被 A 占用。
**修复**: `startup.py` 在 `server.start()` 成功后设置 `artifex_nexus._mcp_server = server; artifex_nexus._adapter = adapter`，与 `__init__.py` 共享同一实例。

### 窗口层级
**问题**: `WindowStaysOnTopHint` 导致面板始终置顶、不随 Max 最小化。
**修复**: 改为 `QtCore.Qt.Tool` 标志 + `QApplication.activeWindow()` 作父窗口 → Tool 窗口行为（随父窗口最小化、不出现在任务栏）。
