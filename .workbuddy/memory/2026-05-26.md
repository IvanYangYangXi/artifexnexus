## Max 插件启动崩溃修复（10:49-11:10）

**现象**: 3ds Max 启动时弹出「启动失败检测」对话框，提示应用程序设置损坏

**根因（对比 artclaw 排查）**:
- artclaw 的 DCCClawBridge 是**自包含**结构（adapters/ + core/ 全在同一目录）
- artclaw 的 `_setup_paths()` 如果找不到目录会直接 return，跳过所有导入
- Artifex 的 SDK (`artifex_nexus_sdk`) 与插件分离，Max/Maya 安装时**未一同部署**
- 部署后的 `scripts/artifex_nexus/` 目录中，max_adapter.py / mcp_server.py / trigger_dispatcher.py
  三文件在模块级别 import `artifex_nexus_sdk` → ImportError → 在 Qt 事件循环中可能触发 Max 进程级异常

### 修复（P0）
1. **dcc_installer.py**: 新增 `_deploy_dcc_sdk()` 通用函数
   - 安装 Max/Maya 插件时自动将 `artifex_nexus_sdk/` 复制到插件目录
   - SDK 源: `packages/dcc/shared/artifex_nexus_sdk/` → 目标: `{scripts}/artifex_nexus/artifex_nexus_sdk/`
   - 从环境变量或 `__file__` 相对路径定位 SDK 源

2. **trigger_dispatcher.py**: 回调脚本路径修正
   - `from v2023.max_addon.trigger_dispatcher` → `from trigger_dispatcher`（扁平部署结构）

3. **__init__.py (Max/Maya)**: 移除 `_addon_dir.parents[4]` 硬编码路径
   - SDK 路径由 startup.py/userSetup.py 统一管理
   - 部署后 SDK 已在 `_addon_dir` 内（自包含设计）

**提交**: 482ad79 → pushed to main
