## 实例工具 file.open.post 触发失效修复（根因×2）

**症状**：`Example-Blender对象命名规范检查 (实例)-01` 设置了文件打开触发，但不生效。

**根因 1 — tool-sources.json 缺少用户工具目录**：
- `~/.artifexnexus/nexus-tools/user/` 从未被注册到 `tool-sources.json`
- Blender trigger_dispatcher 的 `_get_source_dirs()` 从 `tool-sources.json` 读取源目录，扫描不到用户实例工具
- Sidecar trigger_dispatcher 同样受影响（`get_all_manifest_paths()` 读同一配置文件）

**根因 2 — 实例工具目录下无 main.py**：
- 实例工具只有 `manifest.json`，无 `main.py`（脚本沿用父工具）
- 两个 trigger_dispatcher 的 `_execute_tool()` 都直接用 `tool_dir` import `main`，没有 `parentPath` fallback
- importlib.import_module("main") 在实例目录下必然失败

**修复（6 个文件）**：

| 文件 | 修改 |
|------|------|
| `tool-sources.json` | 手动添加 `~/.artifexnexus/nexus-tools`（`user` 类型） |
| `bootstrap.py:_register_default_tool_sources()` | 新增注册用户工具目录 |
| `sidecar.py main()` | 启动时自动确保用户工具目录已注册 |
| `tool_sources.py:register_source()` | 新增 `_normalize_path()` 剥离 `\\?\` 前缀防去重失效 |
| `trigger_dispatcher.py (sidecar)` | `_execute_tool()` 加 parentPath fallback |
| `trigger_dispatcher.py (Blender)` | `_execute_tool()` 加 parentPath fallback |

**parentPath fallback 逻辑**：
```python
entry_path = Path(tool_dir) / entry
if not entry_path.exists():
    parent_path = manifest.get("parentPath", "")
    if parent_path and Path(parent_path).is_dir():
        tool_dir = parent_path  # 使用父工具目录 import
```

**教训**：
- `tool-sources.json` 是三端的唯一数据源（sidecar dispatcher + Blender dispatcher + 共享配置），新增目录类型必须确保注册环节闭环
- 实例工具的脚本 fallback 是隐式约定，需在 dispatcher 层显式实现
