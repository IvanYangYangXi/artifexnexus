## Gateway 状态面板修复：假"运行中"+ 日志刷新提速
- **问题**：Gateway 实际未运行，但系统-Gateway 页面状态显示"运行中"，日志区显示"Gateway 未运行，暂无日志"前后矛盾
- **根因**：sidecar 重启后 gateway_state 单例恢复为 "running" 但 health monitor 未重启，进程退出后无人检测
- **前端修复**（`SystemPage.tsx` GatewayTab）：
  - 新增 TCP 存活检测：`fetchStatus` 拿到 sidecar 的 "running" 后额外 `fetch http://127.0.0.1:{port}/health`（2s 超时）
  - 端口不通 → 状态显示琥珀色"无响应"（`animate-pulse`），dot 旁提示 "(sidecar 报告运行中但端口不通)"
  - 日志轮询提速：1500ms→600ms，首次拉取 batch 50→200，首次立即拉取不等待 interval
  - LogView 新增 `emptyMessage` prop，根据状态显示不同空文案（运行中/无响应/异常/未运行）
  - "无响应"状态按钮显示"强制重启 Gateway"
- **后端修复**（`sidecar_gateway.py` handle_gateway_status）：
  - 反向存活检测：state="running" 时检查 `_current_process.poll()` 或端口探测
  - 进程已死 → 自动修正为 "stopped"（日志 warning）
  - Fallback 恢复 state="running" 后自动重启 health monitor（防止 sidecar 重启后无人监控）
- 测试修复：`test_running_with_log_id` mock `_current_process` 避免误判假 PID 已死
- 改动文件：`SystemPage.tsx`, `sidecar_gateway.py`, `test_sidecar_gateway.py`

## Topbar Blender 状态指示器三态化
- 问题：Blender 未启动仍显示黄色；工具不可用时却显示绿色
- 根因：`dccStatus` 仅 `connected: boolean`，无法区分"进程未启动"和"进程运行中但未连接"
- **mcp_bridge.py**: 新增 `check_blender_mcp_server_running()` — 纯 TCP socket connect（1s timeout，无 MCP 协议）
- **sidecar.py**: status RPC 新增 `blenderServerRunning` 字段
- **openclaw.ts**: `MCPBridgeStatus` 接口新增 `blenderServerRunning` / `upToDate` / `sourceHash` / `deployedHash`
- **AppShell.tsx**: 只有 `blenderServerRunning=true` 时才 push 到 `dccStatus`；`blenderServerRunning=false` → 不显示
- 三态规则：
  - 不显示：Blender MCP Server 未启动（端口无人监听）
  - 黄色：Server 运行中但 MCP 握手未完成
  - 绿色：MCP 握手完成 + 工具可用
