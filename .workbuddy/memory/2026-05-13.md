## Gateway 启动延迟分析 + TASK-0052 创建

### 问题
启动 Artifex → 首条消息回复延迟 50s~109s。

### 根因
Gateway 启动时同步 require() 93 个插件（66 个 enabledByDefault=true，14 个 onStartup=true），
导致 Node.js event loop 饱和，delayMaxMs 峰值 13.7s，CPU 100% 持续 ~120s 才稳定。

### 插件调研结果
- **93 个插件** 分为 11 类：39 AI Provider + 11 工具/能力 + 7 消息通道 + 8 代码/编辑器集成 + 6 语音/TTS + 5 搜索 + 4 设备管理 + 3 多模态 + 3 网关/代理 + 4 实验/工具 + 2 迁移 + 1 协议桥接
- Artifex Nexus 实际仅需 4 个：browser / file-transfer / memory-core / mcp-bridge
- 禁用方式：在 openclaw.json plugins.entries 中设 `"<id>": {"enabled": false}` 即可阻止 require()

### 426 错误
Port 18083 是 Blender MCP Server 的 WebSocket 端口，浏览器以 HTTP 访问触发 426。
DCC 通过脚本通信，不需要浏览器直接访问。修复：mcp_server.py 拒非 WS 连接 + Tauri 封禁。

### 会话 Keep-Alive（gateway-ws.ts + chat-service.ts + ChatView.tsx）
- **gateway-ws.ts**：新增 `sendAgentTurn(sessionKey)` 方法
  - 发送 `agent.turn` RPC，payload: `{sessionKey, message:"heartbeat check", delivery:"none"}`
  - delivery=none：Gateway 不推送响应、不写消息历史，纯静默
  - fire-and-forget：不等待 ACK，静默忽略错误
- **chat-service.ts**：暴露 `sendAgentTurn(sessionKey)` 到 hook 返回
- **ChatView.tsx**：`useEffect` 管理 keep-alive 生命周期
  - 间隔 7 分钟（`KEEPALIVE_INTERVAL_MS = 7 * 60 * 1000`）
  - 仅在 WS 已连接 + 有效 sessionKey 时启动
  - 切换对话/WS 断连时自动清除 timer
  - console.log 标记 start/stop 便于调试
- **效果**：无论离开多久，回来第一条消息就是热会话（GateWay 不会回收进程）
