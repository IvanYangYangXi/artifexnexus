## P0（必修，共 4 条）

### P0-1 · `terminate()` 在没有 `waiting` 时强写 status，会覆盖已 `completed` / `error`

- **文件:行号**：`packages/apps/web/src/features/workflow/engine.ts:193-204`
- **现象**：当工作流已经 `completed` 后用户再点终止按钮，`workflowStatus` 会被强写成 `"terminated"`，覆盖正确的终态；UI/Diff 会变成误报。同理对 `error` 终态。
- **修法**：在方法开头加守卫：
  ```ts
  if (this.workflowStatus === "completed" || this.workflowStatus === "error" || this.workflowStatus === "terminated") {
    return;
  }
  ```
  另把第 202 行的无条件 `this.workflowStatus = "terminated"` 移进「running/paused」分支里，避免和上一段重复赋值。

### P0-2 · `EdgeInspector` 的「标签」编辑用 `edge-add` 触发，会创建一条同 id 的新边

- **文件:行号**：`packages/apps/web/src/components/workflow/WorkflowInspector.tsx:65-71`
- **现象**：dispatch `edge-add` 把已有 edge 再 push 一次，画布会出现"同 id 重复边" + Diff 流也乱（应当是 update 不是 add）。React Flow key 冲突会 warn。
- **修法**：
  1. 在 `workflow-store.tsx` 增加一种 action `{ type: "edge-update"; edgeId: string; patch: Partial<AWFFEdge> }`（diff 也用 `edge-add` 之外新增 `edge-update` 类型）。
  2. EdgeInspector 改成 `dispatch({ type: "edge-update", edgeId: edge.id, patch: { label: ev.target.value } })`。

### P0-3 · `NodeInspector` 的 JSON 配置编辑器：合法 JSON 但不是对象时（如 `"abc"` / `123`）会污染 `node.config`

- **文件:行号**：`packages/apps/web/src/components/workflow/WorkflowInspector.tsx:35-42`
- **现象**：`JSON.parse('"x"')` = `"x"`，被 dispatch 进 `patch.config`，下游 `resolve(node.config ?? {})` 拿到字符串后 `Object.entries` 抛错，引擎崩。
- **修法**：在 try 内增加形状校验：
  ```ts
  const cfg = JSON.parse(e.target.value);
  if (cfg && typeof cfg === "object" && !Array.isArray(cfg)) {
    dispatch({ type: "node-update", nodeId: node.id, patch: { config: cfg } });
  }
  ```
  并在 Textarea 旁加红色"格式无效"提示（受控 state）。

### P0-4 · `ctx.resolve` 模板正则用了带 `g` 的共享实例 + `TPL.test()` 在 `replace` 之前自带副作用

- **文件:行号**：`packages/apps/web/src/features/workflow/ctx.ts:14, 52-66`
- **现象**：`const TPL = /\{\{...\}\}/g` 是模块级 stateful 正则；第 59 行 `TPL.test(s)` 会改变 `lastIndex`，第 60 行虽然重置了 `TPL.lastIndex = 0`，但在并发解析（同一 engine 多次调用 resolve）下仍有竞态；更严重的是当 `s` 不含模板时第 59 行返回 `false`，错失了第 60-66 行的 reset，下一次调用 `lookup`-only 单表达式分支不受影响但下一次 `TPL.test` 仍会从奇怪的 `lastIndex` 开始。
- **修法**：把 `TPL.test` 改成 `TPL = /.../g`-free 的局部正则，或直接判断 `s.includes("{{")`：
  ```ts
  function resolveString(s: string, ctx: RunCtx): unknown {
    const single = s.match(/^\{\{\s*([\w.[\]]+)\s*\}\}$/);
    if (single) return lookup(single[1], ctx);
    if (!s.includes("{{")) return s;
    return s.replace(/\{\{\s*([\w.[\]]+)\s*\}\}/g, (_, expr) => { ... });
  }
  ```
  彻底避免共享正则的 stateful 陷阱。

### P1-1 · `WorkflowInspector` 把 `import { useEngine }` 放在文件中段，违反"imports 顶部"规范且会被工具误判循环依赖

- **修法**：把第 106 行的 `import { useEngine } from "./engine-context";` 移到第 8 行 `import { useWorkflow }` 后面。

### P1-2 · `NodeCanvas.onNodesChange` 末尾 `forceTick + applyNodeChanges(...rfNodes)` 多余且会跳过受控状态

- **文件:行号**：`packages/apps/web/src/components/workflow/NodeCanvas.tsx:77-79`
- **现象**：`applyNodeChanges` 的返回值没有被使用（被 `void` 丢掉）；`forceTick` 是 hack，React Flow 12 不需要外部 force-rerender，rfNodes 已由 useMemo + state.awff.nodes 派生。
- **修法**：删掉第 77-79 行；如果只是为了让 ReactFlow 自身 stash 同步，可改用受控模式：用 `useNodesState` / 完全交给 dispatch。最小改动直接删多余两行。

### P1-3 · `NodeCanvas.onNodesChange` 漏处理 `dimensions` / 拖动中的 position（只在 `!ch.dragging` 时 dispatch）

- **文件:行号**：`packages/apps/web/src/components/workflow/NodeCanvas.tsx:69-70`
- **现象**：拖动中不写 store 是对的（避免高频 Diff），但拖动开始没把 position 同步到 store，会导致拖到一半保存或导出，position 仍是旧值。
- **修法**：在 `ch.dragging === false` 分支增加最终位置 dispatch（当前代码已对，但 React Flow 12 的 `NodeChange.position` 在 `dragging === undefined` 的 select-only 事件里不存在 → 当前 if 同时 `ch.position && !ch.dragging` 已防御；改进点是补一条注释说明这是节流策略）。或直接显式写：
  ```ts
  if (ch.type === "position" && ch.position && ch.dragging === false) { ... }
  ```
  以确保 `ch.dragging` 不为 undefined。

### P1-4 · `engine.applyBranchSkip` 复用 `reachable` 函数但每次调用都做全图 DFS，复杂度 O(N²·E)

- **文件:行号**：`packages/apps/web/src/features/workflow/engine.ts:255-295`
- **现象**：200 节点 ok，500+ 节点 + 多分支时性能堪忧；EPIC 范围内 ok，但需文档化已知边界。
- **修法**：短期：在函数开头记 `// TODO(P1): cache reachable() per branch`。中期：把 reachable 结果按 source 节点缓存到 Map，run 内复用。

### P1-5 · `EngineProvider` 用 `useRef` 单例 engine，但 onChange 闭包 `setSnapshot` 在多次 run 调用间会过期

- **文件:行号**：`packages/apps/web/src/components/workflow/engine-context.tsx:30-37`
- **现象**：engine 单例在组件初始 mount 时一次性构造，`onChange` 绑定第一次 mount 时的 `setSnapshot`。React Strict Mode 二次 mount 时 setSnapshot 引用变化（新组件实例），旧 engine 仍调旧 setState → snapshot 不更新。
- **修法**：把 onChange 改成读 ref：
  ```ts
  const setSnapRef = React.useRef(setSnapshot);
  setSnapRef.current = setSnapshot;
  // engine.onChange = (snap) => setSnapRef.current(snap);
  ```
  或者在 useEffect 里订阅，return cleanup 时取消。最稳的做法是把 engine 提到 module-scope outside Provider，或改用 zustand。
